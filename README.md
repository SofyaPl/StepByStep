# ШагЗаШагом (StepByStep)

Персональный ежедневный задачник как Progressive Web App: день, статусы, повторения без накопления долгов, запасная копия в собственной Google Таблице. Без аккаунта в стороннем сервисе, без подписки, без канбан-досок.

## Зачем это

Коммерческие планировщики обычно тянут иерархию проектов, теги, геймификацию и paywall. Нужно было другое: открыть день на телефоне, записать дело вместе с комментарием, отметить, перенести, настроить повтор для уколов / полива / дней рождения и не потерять историю, если телефон потеряется.

Данные живут локально в браузере. Google Таблица в своей учётке — запасная копия через опубликованный Apps Script, не второй рабочий стол.

---

## Как это сделано

Автор — не разработчик по профессии. Код писался в Cursor: постановка задачи, разбор багов, правки синхронизации и деплой шли в диалоге с агентом, а не из готового ТЗ.

Это важно для чтения кода. Решения вроде гонок автозаписи, `useRef` вместо замыканий и реестра удалённых id появились не как «архитектура с нуля», а как ответы на конкретные поломки: задачи воскресали после удаления, запись в таблицу крутилась каждую секунду, PWA на Windows теряла `localStorage` из‑за очистки cookie при закрытии окна.

## Что умеет приложение

### День как единица планирования

- Горизонтальная лента дат (`DateStrip`): сегодня подсвечен, на каждом дне — счётчик задач.
- Статусы: в плане, сделано, отменено. Выполненные в фильтре «Все» уходят вниз списка.
- Статус `missed` у эпизода цикла появляется не сам по себе на следующие сутки, а когда закрывают более поздний эпизод той же серии. После этого задача уходит во вкладку «Отмена», а не копится в плане.
- Прогресс дня — доля завершённых от общего числа на выбранную дату.
- Разовую задачу можно перенести на завтра или на произвольный день.

### Повторения без снежного кома долгов

Типичный трекер при пропуске ежедневного дела копит просрочку: вчера не сделал зарядку — сегодня висят две. Через неделю — семь. Для курса уколов «каждые 2 дня» или полива это ломает смысл расписания.

Здесь правило другое:

| Ситуация | Что происходит |
|---|---|
| Ежедневный цикл, вчера не сделали | Сегодня в плане один сегодняшний эпизод. Вчерашний остаётся `pending`, но в плашку просрочки не попадает: предлагать перенести его бессмысленно. |
| «Каждые N дней», сегодня дня цикла нет | Вчерашний незакрытый эпизод может всплыть как просрочка с предложением перенести. Когда наступает следующий день цикла, старый долг больше не предлагается. |
| Закрыли эпизод серии | Все более ранние незакрытые эпизоды той же серии получают статус `missed` и уходят во вкладку «Отмена». |

Режимы повтора:

- каждый день;
- каждые N дней (1, 2, 5 — курсы медикаментов, полив);
- выбранные дни недели;
- ежегодно;
- опциональная дата окончания или бессрочно.

Серию можно остановить с выбранного дня, превратить цикл в разовую задачу (текущий день остаётся, будущие pending-экземпляры снимаются), поменять правило или удалить: только этот день / будущее / весь цикл.

Разовые просрочки ведут себя иначе: янтарная плашка предлагает перенести их на сегодня. Цикл туда не смешивается, если на сегодня уже есть плановый эпизод.

### Local-first и Google Таблица

Задачи пишутся в `localStorage` сразу. Телефон — источник правды. Сеть нужна только чтобы сбросить копию в таблицу или один раз восстановиться из неё.

Бэкенд — Google Apps Script (`doGet` / `doPost`) над первым листом книги. Шаблон скрипта копируется из настроек приложения.

Обычный путь — только запись: после локальных правок, если включена галочка, приложение само отправляет текущий список в таблицу с дебаунсом 3 секунды. Кнопка «Сохранить копию в таблицу» делает то же вручную. Параллельный повторный запрос блокируется; если за это время список ещё изменился, после ответа уходит свежая копия.

Чтение из таблицы не запускается при открытии приложения, возврате в окно или сохранении адреса. Единственный путь обратно — кнопка «Загрузить из таблицы»: локальный список заменяется копией, карта удалённых id очищается. Это нужно, если телефон потерялся или приложение стёрлось, а не для ежедневной работы.

### PWA

`display: standalone`, иконки `any` + `maskable`, `start_url` / `scope` под GitHub Pages (`/StepByStep/`). На Windows/Chrome ставится отдельным окном; на Android — WebAPK; на iOS — «На экран Домой» из Safari.

Service worker (Workbox через `vite-plugin-pwa`) кэширует сборку. Обновление: `skipWaiting` + `clientsClaim`, проверка при `visibilitychange`, кнопка принудительной очистки кэша в настройках.

На десктопе Chromium может стирать `localStorage` вместе с cookie при закрытии окон. Если связь с таблицей пропадает после перезапуска PWA — в Chrome: `chrome://settings/content/siteData` → разрешить `https://sofyapl.github.io`.

## Зачем карта удалённых id

Пока таблица была двусторонним источником правды, обычный merge по id ломался так: пользователь удалил задачу → локального id нет → GET из таблицы возвращает старую строку → задача появляется снова.

Сейчас приложение таблицу само не читает, но карта `step_by_step_deleted_ids_v1` (`id → ISO-время удаления`, записи старше 30 дней вычищаются) всё ещё нужна локально. Генерация будущих эпизодов цикла (`ensureRecurringTasks`) её читает: иначе удалённый повтор на дату N создался бы заново при следующем открытии дня. Если удалён корень цикла, отбрасываются и дочерние id (`rec-{parentId}-{YYYY-MM-DD}` и `recurrenceParentId`).

Кнопка «Загрузить из таблицы» карту чистит явно: после потери телефона «этого id больше нет» уже неоткуда знать, а в таблице лежит последняя целая копия.

## CI/CD

Файл: [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml).

Срабатывает на `push` в `main` и вручную (`workflow_dispatch`). Один job на `ubuntu-latest`:

1. `actions/checkout@v4`
2. Node 20 + кэш npm
3. `npm ci`
4. `npm run build` (`tsc && vite build`) — бандл, `sw.js`, `manifest.webmanifest`
5. `actions/configure-pages@v4`
6. `actions/upload-pages-artifact@v3` с `path: ./dist`
7. `actions/deploy-pages@v4`

Права: `pages: write`, `id-token: write`. `concurrency.group: pages`, `cancel-in-progress: true` — новый пуш отменяет незавершённый деплой.

В репозитории GitHub Pages должен быть включён с источником **GitHub Actions**, не ветка `gh-pages`. Публичный URL: `https://sofyapl.github.io/StepByStep/` (`base` в Vite завязан на имя репозитория).

## Установка

### Компьютер (Windows / Mac / Linux)

1. Открыть [приложение](https://sofyapl.github.io/StepByStep/) в Chrome, Edge или Яндекс Браузере.
2. Кнопка **«Установить на ПК»** в шапке или иконка установки в адресной строке.
3. Либо меню браузера:
   - Chrome: «Сохранить и поделиться» → «Установить приложение ШагЗаШагом»;
   - Edge: «Приложения» → «Установить этот сайт как приложение»;
   - Яндекс: «Дополнительно» → «Установить как приложение».

После установки — ярлык, меню «Пуск», закрепление в панели задач, окно без вкладок.

### Android (Chrome / Яндекс)

Меню `⋮` → «Установить приложение» / «Добавить на главный экран».

### iOS (Safari)

«Поделиться» → «На экран Домой».

## Синхронизация с Google Таблицей

1. Создать таблицу на [sheets.new](https://sheets.new).
2. **Расширения → Apps Script**.
3. В приложении: шестерёнка → скопировать шаблон скрипта → вставить в редактор → сохранить.
4. **Развернуть → Новое развертывание**: тип «Веб-приложение», доступ **Все** (`Anyone`). Иначе `fetch` из PWA на GitHub Pages не пройдёт.
5. URL `…/exec` вставить в настройки приложения → **Сохранить адрес**.
6. Галочка «Автоматически сохранять копию в таблицу» по умолчанию включена: после правок копия уходит сама. Кнопка «Сохранить копию» — если нужно записать сразу. «Загрузить из таблицы» — только восстановление.

Первый запрос Google может показать предупреждение о непроверенном приложении — это скрипт в вашей же учётке, не OAuth-клиент стороннего разработчика.
